# DARTY video recording

Local recording branch only. Nothing here publishes or changes football rules,
AI, balance, physics or controls. Without the new flags the usual real-time loop
and audio remain active. The match canvas always fills its viewport; resize only
updates renderer size and camera aspect, keeping existing FOV/follow rules.

## Launch

Use Quick Play normally to choose teams and start a **CPU vs CPU spectator**
match. Copy the complete match URL, including its `#flMatch=...` fragment, then
add these query flags **before** the fragment:

```text
http://127.0.0.1:4331/match-engine/match.html?quickPlay=1&engine=fl-v2&candidate=5&simulationSeed=1772652239&autoplay=1&capture=1&clean=1&director=showcase&matchMinutes=6#flMatch=<the original encoded spectator configuration>
```

The fragment and query seed must match. A bare match URL without the existing
V2 launch contract remains rejected. Single-player capture also works with its
original contract; spectator mode gets actions without human input.

| Flag | Effect |
| --- | --- |
| `capture=1` | Frozen real-time loop, virtual 60 Hz simulation, 30 fps API, no audio or connected controllers. |
| `clean=1` | Only pitch view, DARTY badge and neutral score/time remain. Hides sheets, names, prompts, toasts, overlays and name-bearing textures; blanks kit crests/sponsors and replaces stadium/ad text with DARTY. Simulation identities remain intact. |
| `director=showcase` | Existing dynamic/classic rigs hold most live play. Brief end-to-end, broadcast and tactical holds add variety. Shots/hard hits cut to classic; existing goal replays remain, and confirmed pops use the existing contact replay. |
| `matchMinutes=2..20` | Existing real match duration; the default is 6. Match-clock time is accelerated, exactly as in normal play. |
| `simulationSeed=<integer>` | Existing V2 seed; must agree with the saved fragment. |

Flags are independent: clean and showcase can run with the normal loop.
There was no `minute=` seek support in this host. Use `findNext` or step normally;
this patch does not forge a clock jump. `fast=1` is ignored in capture so each
video frame always represents precisely 1/30 second. Keep the same fragment,
flags, viewport, device pixel ratio and browser/GPU for repeatable footage.
Capture isolates saved camera/walkout/testing preferences and does not write
recordings into the normal browser match log.

## `window.dartyCapture` (only with `capture=1`)

| API | Result |
| --- | --- |
| `await ready` | Match initialised, scene/environment texture loaded, first frame rendered. Rejects on startup/asset failure. Does not skip the walkout. |
| `step(n = 1)` | Synchronously runs exactly `2*n` existing 1/60 s ticks, advancing timers, animations, camera and particles, then renders once. Returns video frame index. `n` must be a non-negative integer; `step(0)` redraws without advancing. |
| `frame()` | Current zero-based video frame; initial image is frame 0. |
| `time()` | Current **match-clock seconds**, including the normal stopped-clock/replay behaviour. |
| `events()` | Detached copy of the recording event log. |
| `findNext(type, maxSeconds = 60)` | Advances up to `floor(maxSeconds*30)` frames until a **new** matching event, rendering once at the end. Returns its frame index, or `null`. It is a forward search, not a rewind; simulation can still be slow. |
| `forceGoalAttempt()` | Calls the existing G guaranteed-goal **testing aid**, temporarily enabling it without changing saved preferences. Returns `true` if accepted, `false` during walkout/restart/replay/etc. Footage from this aid is staged, not an organic goal. |

Event rows contain `{type, time, frame, camera: {mode, rig}, ...}`. The types are
`kickoff`, `pass`, `shot`, `goal`, `save`, `tackle`, `slideTackle`, `hardHit`,
`pop`, `foul`, `freeKick`, `penalty`, `replayStart`, `replayEnd`, `celebration`,
plus `camera` for rig changes. Confirmed contacts come from committed Movement
V2 telemetry; action/save/restart/pop rows come from existing host signals.
Rows may include neutral team/player IDs and `sourceType`; testing-aid shots
carry `testingAid: true`. No outcome is generated by the log or camera director.
`frame` indexes output images; two events can share a frame. Initial kickoff
staging can be logged before the later on-pitch kickoff.

The pop replay uses the existing player/ball contact snapshots and restores live
state on completion. Detached-part flights/particles play in the live shot;
the inherited replay snapshots do not rewind those meshes. Existing scripted
walkout, celebration, restart and replay camera sequences take priority over
the five live showcase presets.

## Frame capture (Puppeteer-style)

Start the README's local static server. `matchUrl` below is the complete URL
obtained through setup, with the flags above. Use already-installed tooling.

```js
const browser = await puppeteer.launch({headless: true});
const page = await browser.newPage();
await page.setViewport({width: 1280, height: 720, deviceScaleFactor: 1});
await page.goto(matchUrl);
await page.evaluate(() => dartyCapture.ready);
for (let frame = 0; frame < 300; frame++) {
  if (frame) await page.evaluate(() => dartyCapture.step());
  await page.screenshot({path: `frames/${String(frame).padStart(6, '0')}.png`});
}
const events = await page.evaluate(() => dartyCapture.events());
await browser.close();
// Encode the saved PNGs at 30 fps with your existing video tools; no audio track.
```

To locate a goal/pop, use a separate scouting run with `findNext`. Save the event
frame, reload the same URL, then capture every frame through it for the lead-in.
A goal-aid example after ordinary play starts:
`await page.evaluate(() => dartyCapture.forceGoalAttempt())`, followed by
`await page.evaluate(() => dartyCapture.findNext('goal', 2))`.
